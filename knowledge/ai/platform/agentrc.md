# AgentRC (repo context generation and scoring)

`microsoft/agentrc` is a CLI, VS Code extension, and CI check that **prepares a repository for AI-assisted development**. It runs a three-step loop: *measure* the repo's AI-readiness against 9 pillars and a 5-level maturity model, *generate* the instruction files, MCP config, and eval suite that close the gaps, then *maintain* them by evaluating whether the instructions still improve agent responses. Instructions are generated by reading the actual codebase via the Copilot SDK — not filled into templates. MIT-licensed and explicitly labelled **experimental with breaking changes expected** as of 2026-08-10.

Official: [microsoft/agentrc](https://github.com/microsoft/agentrc)

Where [`apm.md`](apm.md) *distributes* agent context, AgentRC *authors* it — the two share the `.instructions.md` format and are designed to be used together.

## Installation

```bash
npx github:microsoft/agentrc          # interactive hub
npx github:microsoft/agentrc readiness
```

Requires Node.js 20+, and the **Copilot CLI** (bundled with the GitHub Copilot Chat VS Code extension) logged in via `copilot` → `/login`. GitHub auth comes from `gh auth login` or `GITHUB_TOKEN`; Azure DevOps uses `AZURE_DEVOPS_PAT`.

> **Note**: the npm package named `agentrc` is an unrelated third-party placeholder (`0.0.0`, 313 bytes). Install from the GitHub repository, as above.

## The loop

| Step | Command | Output |
|---|---|---|
| Measure | `agentrc readiness` | Readiness score, maturity level, list of missing context |
| Generate | `agentrc instructions` / `agentrc generate mcp` / `agentrc generate vscode` | `AGENTS.md` or `.github/copilot-instructions.md`, `.vscode/mcp.json`, `.vscode/settings.json` |
| Maintain | `agentrc eval --init` then `agentrc eval agentrc.eval.json` | `agentrc.eval.json` test cases plus a pass/fail verdict per case |

Other entry points: `agentrc init` (one-time setup), `agentrc batch` (across an org), and `agentrc pr owner/repo` (opens an automated PR against any repo). Works with GitHub and Azure DevOps, and supports monorepos and multi-root VS Code workspaces.

## Maturity model and pillars

| Level | Name | Meaning |
|---|---|---|
| 1 | Functional | Builds, tests, basic tooling in place |
| 2 | Documented | README, CONTRIBUTING, custom instructions exist |
| 3 | Standardized | CI/CD, security policies, CODEOWNERS, observability |
| 4 | Optimized | MCP servers, custom agents, AI skills configured |
| 5 | Autonomous | AI-native development with minimal oversight |

The score comes from 9 pillars: **Repo Health** — Style, Build, Testing, Docs, Dev Environment, Code Quality, Observability, Security — plus **AI Setup** (custom instructions, MCP servers, agent configs, skills). From Level 2 up, AgentRC also flags **instruction inconsistency**: divergence between `copilot-instructions.md`, `AGENTS.md`, and `CLAUDE.md` in the same repo, and suggests consolidation.

Organizations can reshape the scoring with **policies** that disable inapplicable criteria, override impact/required level, or set thresholds.

## Instruction generation

- `--output AGENTS.md` is the recommended form (portable across Copilot, Claude, and others); the default target is Copilot-only `.github/copilot-instructions.md`.
- `--strategy flat` (default, one root file) or `--strategy nested` (root hub plus per-topic files under `.agents/`) for large repos.
- `--areas` / `--area <name>` / `--areas-only` generate per-area instructions in monorepos; areas come from `agentrc.config.json` or auto-detection. These map onto VS Code `.instructions.md` files with `applyTo` patterns.

## Evaluation as a drift gate

The eval framework answers "do these instructions still help?" — for each case it compares the agent's response **with and without** the instructions and has a judge model pick the better one. That A/B framing is what makes the score meaningful rather than an absolute quality guess.

```json
{
  "cases": [
    {
      "id": "add-feature",
      "prompt": "Add a new CLI command that lists all detected areas",
      "expectation": ["Identify which files to create/modify", "Implementation steps", "Verification steps"]
    }
  ]
}
```

All AgentRC JSON files accept `//` and `/* */` comments (JSONC). Both gates exit `1` on failure, so they drop straight into CI:

```bash
agentrc readiness --fail-level 3 --json      # minimum maturity level
agentrc eval agentrc.eval.json --fail-level 80  # minimum pass rate (%)
```

## Common AI Agent Mistakes

1. **Installing `npm i agentrc`** — that name is an unrelated placeholder package. Use `npx github:microsoft/agentrc`.
2. **Expecting deterministic output** — instructions are model-generated from the repo, so two runs differ. Review the diff before committing rather than treating it as a formatter.
3. **Generating Copilot-only instructions in a multi-agent repo** — the default writes `.github/copilot-instructions.md`; pass `--output AGENTS.md` when Claude Code / Codex also read the repo.
4. **Reading the readiness score as code quality** — it measures *context available to agents*, not correctness or test coverage.
5. **Treating it as stable** — the project ships an explicit experimental warning; pin a commit if reproducibility matters.
